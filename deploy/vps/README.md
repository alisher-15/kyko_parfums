# Kyko Parfum на своём сервере в Казахстане

Для домена `.kz` и по закону о персональных данных сайт и база должны работать на сервере в
Казахстане. Этот комплект поднимает всё на одном VPS любого казахстанского хостинга (ps.kz,
hoster.kz и т. п.): PostgreSQL, сайт (тот же образ, что на Render) и Caddy, который сам получает
и продлевает HTTPS-сертификат.

## Что нужно

- VPS: Ubuntu 24.04, 2 vCPU, 4 ГБ памяти, от 25 ГБ диска.
- Домен (например, `kyko.kz`), у которого A-запись указывает на IP сервера; если нужен `www`,
  ещё A-запись `www` на тот же IP.

## Первый запуск

Одна команда под root, на чистом сервере или рядом с другим проектом:

```bash
curl -fsSL https://raw.githubusercontent.com/alisher-15/kyko_parfums/main/deploy/vps/install.sh | bash
```

`install.sh` сначала смотрит на сервер (память, диск, кто занял порты 80/443). Если порты
держит другая программа, он ничего не меняет и говорит, какая. Иначе он:

1. добавляет подкачку 4 ГБ, если её нет (сборке сайта нужно ~2 ГБ памяти);
2. ставит Docker и git;
3. скачивает код в `/opt/kyko`;
4. пишет `deploy/vps/.env` с новыми паролями базы и JWT, спрашивая только email и пароль
   владельца;
5. собирает и запускает сайт, базу и Caddy (10–15 минут, лог в `/var/log/kyko-install.log`);
6. проверяет, что сайт отвечает, и ставит ночную копию базы.

Без домена магазин открывается на `https://<ip-через-дефисы>.sslip.io` с настоящим сертификатом.
Когда A-запись домена укажет на сервер, та же команда переводит магазин на него:

```bash
curl -fsSL https://raw.githubusercontent.com/alisher-15/kyko_parfums/main/deploy/vps/install.sh | DOMAIN=kyko.kz bash
```

Почта, Telegram, Sentry, аналитика и R2 — в `/opt/kyko/deploy/vps/.env` (образец —
`.env.example`), затем `cd /opt/kyko/deploy/vps && docker compose up -d --build`.

## Наполнение магазина из Excel

База пустая: каталог, цены и связи с прайсами возвращаются из файлов, остатки — пересчётом.
Сначала фото флаконов — в R2, чтобы все фото магазина были в одном месте (нужны `R2_*` в `.env`):

```bash
docker compose exec -w /app/backend app python -m app.cli photos-to-r2
```

Затем войдите в админку владельцем и по порядку:

1. **«Импорт Excel»** → последняя выгрузка каталога («Экспорт в Excel» из админки). Сначала
   проверка без сохранения, затем загрузка. Вернутся товары, объёмы, тестеры, три цены и
   себестоимость, штрихкоды, описания и ссылки на фото — такими, какими были на дату выгрузки.
2. **«Поставщики»** → Канат → загрузить файл сопоставления, затем прайс → проверить → «Применить».
   То же для Эрика. Вернутся связи строк прайса с товарами, цены поставщиков и актуальные цены.
3. **«Инвентаризация»** — пересчитать остатки со сканером: в выгрузке остатков нет.
4. **«Настройки»** — пороги цен, получатели Telegram, курс; **«Акции»** — заново. Оптовым
   клиентам — зарегистрироваться снова, роли поставить в «Пользователях».

Ссылки на фото из выгрузки продолжают работать: загруженные через админку уже в R2 (впишите в
`.env` те же `R2_*`, что на Render), а `/bottles/…` импорт сам заменяет на копии в R2.

## Обновление

После мерджа в `main`:

```bash
cd /opt/kyko && git pull && cd deploy/vps && docker compose up -d --build
```

Миграции применяются при старте. Если новая версия не стартует, верните предыдущую:
`git checkout <прошлый коммит> && docker compose up -d --build` — база останется совместимой
(см. «Миграции и откат неудачного деплоя» в основном README).

## Резервные копии

`backup.sh` делает дамп базы в `/var/backups/kyko` и хранит последние 14. Каждую ночь в 3:15:

```bash
crontab -e
15 3 * * * /opt/kyko/deploy/vps/backup.sh >> /var/log/kyko-backup.log 2>&1
```

Копия на том же сервере не спасёт, если сервер пропадёт: раз в неделю забирайте последний файл
к себе (например, `scp root@<сервер>:/var/backups/kyko/kyko-*.dump .`) и заодно скачивайте
«Экспорт в Excel» из админки. Восстановление дампа (сайт остановлен):

```bash
docker compose stop app
docker compose exec -T db pg_restore -U kyko -d kyko --clean --if-exists < kyko-<дата>.dump
docker compose up -d app
```

## Мониторинг

UptimeRobot на `https://<домен>/api/health` (см. основной README): если сайт или база упадут,
придёт письмо или сообщение в Telegram. Логи: `docker compose logs --tail 200 app`.
